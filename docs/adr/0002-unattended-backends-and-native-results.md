# Unattended Backends and Native Agent Results

**Status: accepted.** Review Jobs use Unattended Execution: no backend may depend on interactive permission prompts, and each adapter explicitly enables only the tools required by the Shared Review Skill. Codex keeps its native workspace sandbox, Claude uses its native tool permissions, and Pi runs with the worker account's host permissions; permitted Claude Bash commands likewise inherit the worker account rather than an OS sandbox. Backend network access is unrestricted so review, delivery, dependency access, and web search remain available. Pi ignores project-local settings, extensions, prompts, context auto-loading, and skills, then loads only the snapshotted Shared Review Skill and explicit built-in tools.

The worker uses the web service's OS account by default, while deployments may run it under a dedicated account. Local Agent and platform CLIs use the installation, authentication, and permissions already configured for that account; an OpenCode Serve deployment uses the corresponding tools and credentials in its remote execution environment. The project does not issue, restrict, proxy, or validate CLI permissions; it provides platform CLI example commands in the Shared Review Skill and preserves the documented runtime inputs needed by the selected CLI.

The service owns the stable Review Job Record and stores each backend's Agent Result in its native text, JSON, or JSONL form instead of requiring model-generated cross-backend JSON. `completed` means only that the backend process exited successfully; it does not assert that a review note or fix MR was delivered. Backend Timeout applies only to Agent execution. Its default `-1` means unlimited; a positive value enables the deadline. Git preparation, OpenCode session establishment, and cleanup retain separate positive timeouts. When Agent execution times out or worker shutdown grace expires, the worker terminates local backend process groups, waits a short bounded grace, and force-kills survivors. A remote OpenCode execution is aborted through the session API so unlimited normal execution never makes worker shutdown unlimited. Cleanup then receives its own bounded grace.

Agent Result storage has no default application-level size limit. A deployment may configure a maximum; when enabled, the service preserves the beginning and end of oversized output with an explicit truncation marker and records `result_truncated` rather than silently presenting it as complete.

The service stores backend stdout as Agent Result even when the backend exits unsuccessfully. For failures, redacted stderr becomes the Review Job `error`; stdout and stderr are not merged because that would corrupt native JSON or JSONL. Cleanup failure is recorded independently as `cleanup_error` and never changes the Execution Status already determined by backend execution.
