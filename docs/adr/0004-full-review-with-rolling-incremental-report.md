# Full Review with Rolling Incremental Report

**Status: accepted.** Every Review Job checks the complete current merge/pull request diff from `merge-base(TARGET_REVISION, SOURCE_REVISION)` through `SOURCE_REVISION`. A later source revision can change the meaning of earlier lines, so `PREVIOUS_REVIEWED_SOURCE_REVISION..SOURCE_REVISION` must never become the correctness boundary.

For reporting, the Agent uses `PREVIOUS_REVIEWED_SOURCE_REVISION..SOURCE_REVISION` to identify changes introduced since the last delivered review. New findings are emphasized. Existing findings are repeated only when their status needs to be updated, such as remaining unresolved or becoming fixed. If there is no previous reviewed revision, the whole current diff is new for reporting purposes. If history was rewritten and the previous revision is no longer an ancestor of the current source, the Agent still performs the full correctness review, abandons the Git delta range, compares finding state semantically against the previous note, and marks the snapshot as history rewritten.

Each merge/pull request owns one automation-owned Rolling Review Note. The first delivered review creates it and later revisions replace its complete body with a current snapshot containing the current revision, newly introduced or changed findings, unresolved findings, and findings fixed since the previous review. Human edits to that note are not preserved. Findings receive simple stable keys such as `F001`; the Agent combines those keys with semantic comparison to carry finding state across revisions without a structured finding JSON contract.

The note body includes a deterministic hidden marker. Platform create/update response is written unchanged as provider-native JSON to a fixed delivery receipt. A provider adapter extracts only the note ID and URL; the Agent does not construct a normalized receipt. If the stored ID is absent or the note was deleted, the Agent searches for the marker and creates a new note only when recovery fails.

The Review Job Record carries `previous_reviewed_source_revision`, `previous_review_note_id`, and `delivery_status`. Delivery Status is `not_attempted` before the Agent starts, `confirmed` only after a valid receipt, and otherwise `unconfirmed`; it remains independent from backend Execution Status. The Shared Review Skill receives `TARGET_REVISION`, `SOURCE_REVISION`, and `PREVIOUS_REVIEWED_SOURCE_REVISION` and is responsible for full-diff validation, delta-aware reporting, and updating the existing platform note. `previous_reviewed_source_revision` advances only after a successful create/update delivery receipt, not merely because the backend exited successfully.
